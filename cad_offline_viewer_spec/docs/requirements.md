# 要件定義書：オフラインCAD図面（PDF）検索・閲覧システム

## 1. 目的
CAD図面をPDF化（OCR済）したデータを、インターネット非接続環境でも迅速に検索・閲覧できるようにし、災害時でも利用継続可能で、四半期ごとの更新を差分配布で安全に適用できる運用基盤を提供する。

## 2. 背景・課題
- 図面PDFが大量に存在し、必要な図面を現場で即時に探せない
- マルチPDF（複数図面を一式に束ねたPDF）が多く、検索と更新が煩雑
- クラウド利用が困難な環境（機密・規制・災害対策）
- 更新時の全入替は現場負荷が高く、差分更新が求められる
- 現場はスマホ利用が中心で、PC操作が前提だと利用が定着しない

## 3. スコープ

### 3.1 対象データ
- 入力：PDF（OCR済またはOCRテキスト抽出可能）
- データ規模：最大 50,000 PDF未満（論理図面単位）
- 形式：単体PDFとマルチPDFが混在（マルチが比較的多い）

### 3.2 利用者
- 現場利用者：スマホで検索・閲覧のみ（更新・編集は不可）
- 管理者：Windows PCで取り込み、分割、メタ整備、索引生成、差分生成
- 現場更新担当：Windows箱で差分パック適用（手順は最小）

### 3.3 システム範囲
- メンテナンスPC（Windows）
- 箱（現場配布先Windows）：PWA配信、検索API、PDF配信
- スマホPWA：検索・閲覧

## 4. 前提条件・制約
- インターネット不要（オフライン運用）
- 現場内のローカルWi-Fiは利用可（箱に接続して閲覧）
- 更新頻度：四半期に1回程度
- 改訂欄は無い、ヘッダ固定ではない（画像テンプレ前提の自動分割は不可）
- 年月とタイトルは存在（テキスト特徴量ベースの自動分割＋半自動補正を採用）

## 5. 用語定義
- Container：元のPDF（単体/マルチを含む原本単位）
- Slice：論理図面単位（検索・閲覧・差分更新の最小単位）
- Box（箱）：現場に設置するWindows端末。PWAと検索APIとPDF配信を提供
- A/Bスロット：更新適用先を稼働中と非稼働に分離し、事故時に即ロールバック可能にする方式

## 6. 機能要件（FR）

### FR-01 データ取り込み（管理者）
- PDF（単体/マルチ）を取り込み、Containerとして保存する
- Containerに一意ID（UUID）を付与し、追跡可能にする
- 入力元パス、取り込み日時を記録する

### FR-02 マルチPDFの正規化（分割）とメタ生成（管理者）
- マルチPDFをSlice（論理図面単位）へ分割する
- 目次がある場合は目次を優先利用する
- 目次がない場合はOCRテキストから 年月＋タイトル を主シグナルとして境界候補を推定する
- 自動分割には信頼度スコア（0–1）を付与し、閾値未満は要手動レビューに回す
- 手動レビューで境界を確定できる（半自動運用）

### FR-03 メタデータ管理（管理者）
- Slice単位にメタデータを持つ（title, drawing_no, facility, area, year等）
- メタの手修正が可能
- 図面番号がない場合はnull許容

### FR-04 サムネ生成（管理者）
- Slice PDFのサムネイルを生成する（最低：1枚目）
- 必要に応じてページサムネ（全ページ/一部）を生成できる

### FR-05 検索インデックス生成（管理者）
- Slice単位＋ページヒット情報を持つ全文検索インデックスを生成する
- 検索対象：OCRテキスト＋メタデータフィールド
- フィルタ：facility / area / year（最大3）を基本搭載する

### FR-06 リリース生成（管理者）
- リリース版（例：2026Q2）として manifest を確定する
- 件数、生成日時、生成ツールバージョン等を記録する

### FR-07 差分パック生成（管理者）
- from/toリリースから差分（追加/更新/削除）を算出し ZIP を生成する
- 差分パックに以下を含める：
  - delta_manifest.json / checksums.txt / deleted.json
  - added/ updated/（対象ファイル）
  - report.csv（変更一覧）
- 差分更新単位はSliceを基本とする（Containerは必要時のみ）

### FR-08 箱側：PWA配信・検索API・PDF配信（現場）
- Windows箱上でローカルWebサーバとして稼働する
- /app でPWAを配信する
- /api/v1/search 等のAPIを提供する
- /api/v1/slices/{id}/pdf は Range対応でPDFを配信する

### FR-09 箱側：差分適用とA/B切替（現場更新担当）
- 差分パックは非稼働スロットへ適用し、検証後に切替する（A/B方式）
- 適用失敗時は稼働中スロットを維持する
- ロールバックは active_slot.txt の戻しで成立する

### FR-10 スマホPWA：検索・閲覧（現場利用者）
- 画面導線：検索→結果→閲覧（3タップ以内を目標）
- サジェスト、フィルタ（最大3）、結果カード、ヒットページジャンプ
- お気に入り/履歴（端末ローカル）
- オフライン時はアプリ起動と履歴・お気に入り閲覧が可能（PDF全件オフラインは要件外）

## 7. 非機能要件（NFR）
### NFR-01 性能
- 50,000 Slice未満で検索が実用（目安：数秒以内）
- PDF閲覧はズーム/パンが破綻しない（Range配信必須）

### NFR-02 可用性・災害耐性
- A/Bスロットで直近2世代を保持可能
- 復旧手順は簡潔（箱起動→PWAアクセス）

### NFR-03 セキュリティ
- 外部通信なし
- 箱のAPIはローカルサブネット限定（FW＋アプリ設定）
- 操作ログを保持（個人情報は最小）

### NFR-04 保守性
- メンテ手順がCLIで再現可能（ログ/失敗一覧/再実行）
- スキーマ・manifest・差分パックの仕様が固定される

### NFR-05 互換性
- メンテPC：Windows 11
- 箱：Windows 11（サービス稼働）
- クライアント：iOS Safari / Android Chrome

## 8. スコープ外
- CADネイティブ（DWG/DXF等）の表示・編集
- スマホからの登録・更新
- クラウド同期
- 図面への注釈・手書きマークアップ

## 9. 受入基準（総合）
- 取り込み→分割→索引→リリース→差分生成が再現可能
- 箱に差分を適用してA/B切替できる
- スマホで検索→閲覧→ヒットページジャンプができる
- ロールバックが即時にできる
- ログと失敗一覧で原因追跡できる
